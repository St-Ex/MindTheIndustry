# DECISIONS.md — Active Decisions

The decisions currently in force for this repo. Agents: read this before making
any change. Keep this file limited to active decisions — when one is superseded,
replace its entry. The history of past decisions lives in the git log, not here.

## Workflow & repo

- **Work on `main` directly.** Never push without explicit owner approval. Commits in English, one topic per commit.
- **Never force-push.** If a branch diverges from its origin with duplicate commits, rebase onto origin (git drops the duplicates automatically).
- **English-only repo**: docs, comments and user-facing strings.
- **Java 17 via mise**; `mise build` builds `build/libs/mindtheindustryDesktop.jar`. Mindustry/Arc dependencies are `compileOnly` — never bundle the engine inside the mod jar.
- **Intent tracking**: backlog in GitHub Issues; non-trivial active features get an `openspec/changes/<slug>/` proposal (format in `openspec/project.md`). Small fixes go straight to a PR.

## Architecture & branding

- **Everything is named after the mod**: display name, mod id, package `mindtheindustry`, main class `MindTheIndustryMod`, `/mindtheindustry` command. "Rogue-like" survives only as the genre word in prose.
- **Game logic never depends on `arc.scene`.** The `ui/` layer only renders state; every mechanic (reward, modifier, synergy, wave) must exist and be testable without a UI. No purely visual content without a gameplay counterpart.
- **Deterministic, seeded logic**: the run seed drives reward generation and all network-synced randomness, so server and clients stay in sync; tests use fixed seeds (`new Rand(42)`, `session.start(42)`).
- **Run entry point = the "MTI" planet in the New Game menu.** A mod-created `Planet` (display name `MTI`, a dwarf moon of Serpulo: small radius + `Planets.serpulo` parent, `alwaysUnlocked = true`) appears automatically in the planet menu with a single selectable sector (only `startSector` is selectable, so the globe shows one marker). It has its OWN tech tree (root = the run `SectorPreset`, created in `init()` before `super.init()`) — never clone/share Serpulo's tree, because `new TechNode(...)` reassigns `content.techNode` and would leak into the campaign. Buildability on MTI is registered directly: `init()` adds the planet to `shownPlanets` of all blocks/units (a block only shows in the construction HUD on a planet in its `shownPlanets` — `environmentBuildable()`); this is additive and does not affect other planets. Its start sector is bound to the vanilla **labyrinth** map via a `SectorPreset` (`default/labyrinth`), and launching it auto-starts the run (`PlayEvent`). Run control is the server-registered `/mindtheindustry` command (works identically in solo and multiplayer — solo runs an integrated server, so `ServerLoadEvent` fires there too); reward picking is a HUD box (`ui/RewardChoicePanel`) fed by `RewardChoicesPacket` S→C, votes go back via `RewardVotePacket` C→S. The server controller is initialized on `ServerLoadEvent` with `PlayEvent`/`WorldLoadEvent` fallbacks, so the mod works in solo, hosted and dedicated games. The planet also carries a procedural generator (`SerpuloPlanetGenerator` subclass, random `seedOffset` per launch) for any sector without a preset.
- **Difficulty curve & bosses**: every wave start rebuilds `state.rules.spawns` via `core/WaveDesigner.buildSpawns(wave, session.rand)` — vanilla `Waves.generate` scaled by `DifficultyTuning.difficultyForWave(wave)`, vanilla's random bosses stripped, one `StatusEffects.boss` group added every `bossInterval` (20) waves. All tuning knobs are static fields in `core/DifficultyTuning`. Seeded → deterministic per run.
- **Basic plans unlocked at run start**: `STARTER_BLOCKS` + `STARTER_UNITS` in `MindTheIndustrySession` are unlocked for the group on `start()` (so also excluded from later PLAN offers). Besides cores/turrets/walls/drills/production/units, the starter set covers the basic blocks of the `distribution`, `liquid`, `power`, `effect` and `logic` categories — but NOT batteries or advanced generators (`thorium-reactor`, `impact-reactor`), which stay as PLAN rewards. Unlocking goes through `unlockForGroup`, which sets the in-memory `unlocked` flag via `core/UnlockFlags` (reflection — NEVER `content.unlock()`, which persists to global settings and would leak into the campaign) + fires `UnlockEvent` (engine broadcasts `Call.researched` to clients) + `state.rules.researched.add` (client-side build menu reads `rules.researched`; the host reads the `unlocked` flag via `unlockedNowHost()`). On MTI map load, `isolateUnlocks()` hides everything not in the group (campaign unlocks don't leak INTO the MTI menu); on leaving, `restoreUnlocks()` puts the flags back. All in-memory — Core.settings is never touched, so both modes stay isolated in both directions.
- **Post-wave rewards = one of each category x rarity**: the 3 choices after a wave are always exactly one TRADEOFF (+X% one stat / −X% another, whole group), one PLAN (1/2/4 building or unit unlocks for the group, never duplicating content offered in the same round), and one RESOURCE gift (items to the team cores); the box order is shuffled per wave (seeded). Rarity NORMAL(grey)/RARE(blue)/EPIC(violet) multiplies magnitude x1/x2/x4 (±10% base trade, 100 base resources). Knobs: static fields in `rewards/Rarity` and `core/RewardGenerator`. Seeded → deterministic per run. No schematics, no per-player targeted bonuses in the reward pool. Choices are picked by clicking icons in the HUD box (not via chat command); the `ui/` layer only renders `ClientRewardState` and sends vote packets — all logic stays server-side in `core/`.
- **Backlog flag**: build a dedicated run map with the map editor later (instead of reusing labyrinth).

## Validation

- **Headless tests only** — never validate a change by launching the game manually from an agent. Tests live in `tests/` (JUnit 5) and boot Mindustry headless once per JVM via `HeadlessMindTheIndustryTest`.
