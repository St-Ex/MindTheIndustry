# Design: procedural run planet

## Engine mechanics (Mindustry v160, `../Mindustry`)

- A mod registers a planet by creating a `Planet` in `loadContent()`; the New
  Game planet menu (`ui/dialogs/PlanetDialog`) lists `content.planets()`
  automatically — no custom UI needed.
- `world.loadSector(sector, params)` (`core/World.java:265`): if the sector has
  **no `SectorPreset`** and `sector.planet.generator != null`, the map is
  generated by `planet.generator.generate(tiles, sector, params)`.
- `PlanetGenerator.generate(tiles, sec, params)` seeds its `rand` with
  `sec.id + params.seedOffset + baseSeed` (`maps/generators/PlanetGenerator.java:188`).
  Normal gameplay launches pass `seedOffset = 0`, so we randomize it ourselves
  per launch → a different map every run.
- The planet menu shows a planet only if `selectable(planet)`
  (`PlanetDialog.java:607`): `alwaysUnlocked && isLandable()`, or a sector with a
  base. We set `alwaysUnlocked = true`.
- The planet constructor with `sectorSize = 3` auto-creates one sector per grid
  tile; `startSector = sectors.first().id` (0) is immediately selectable
  (`PlanetDialog.canSelect`, `PlanetDialog.java:426`: `sector.id == planet.startSector`).
  `Planet.getSector(Ptile)` is index-based (`sectors.get(tile.id)`), so the grid
  sectors must stay — do not clear them or add a `Ptile.empty` sector (its id 0
  would collide and be unreachable).
- A sector **with** a `SectorPreset` loads its map from the preset's
  `FileMapGenerator` (`maps/<planet>/<map>.msav`, then `maps/<map>.msav`); a sector
  without a preset uses `planet.generator`. Our start sector gets
  `new SectorPreset("run", "default/labyrinth", planet, 0)` → the vanilla
  `maps/default/labyrinth.msav`.
- Multiplayer: the host generates/loads the map during `loadSector`; clients
  receive the map over the network.

## New classes

- `content/MindTheIndustryPlanet extends Planet` — name `mindtheindustry`,
  parent `Planets.sun`, `alwaysUnlocked = true`, `generator` =
  `MindTheIndustryPlanetGenerator`, `startSector = sectors.first().id`, and a
  `SectorPreset` binding the start sector to `default/labyrinth`.
- `content/MindTheIndustryPlanetGenerator extends SerpuloPlanetGenerator` —
  reuses the main campaign's native procedural generation; overrides
  `generate(Tiles, Sector, WorldParams)` to set a random `params.seedOffset`
  when the engine passed 0 (normal launches), then delegates to super.

## Run start

- `MindTheIndustryMod.loadContent()` creates the planet.
- `Events.on(WorldLoadEvent)`: if `state.rules.sector` belongs to our planet,
  force run-friendly rules (`waves = true`, `waveTimer = true`, `winWave = 0`).
- `Events.on(PlayEvent)`: ensure the server controller exists; if the current
  sector is ours, call `serverController.startCommanderSelection()` — the run
  auto-starts on launch.

## Control channel: server command only

- `/mindtheindustry` moves from `registerClientCommands` to
  **`registerServerCommands`** (solo's integrated server and hosted/dedicated
  servers both handle it; chat commands reach the server in both modes).
- Server controller notifies players via `player.sendMessage(...)` (chat) —
  works in solo and multi, no packets, no `Core.app.post` hacks.
- Subcommands: `start|stop|skip|status|commanders|unlock-all|vote <i>|
  reward <i> [target]|active <entityId> <isBuilding> <playerName|none>`.

## Removed (broken, superseded by the above)

- `ui/` package: `MindTheIndustryHUD`, `CountdownHUD`, `RewardDialog`,
  `EntityPlayerSelector`.
- `meta/CommanderSelectionDialog`, `core/ClientMindTheIndustryController`.
- All packets except `SchematicUnlockPacket` (S→C, used by `SchematicReward`
  to deliver schematic data to clients).

## Tests (headless, `tests/`)

- Generator: same seed → identical map; different seedOffset → different map;
  generated map is non-empty.
- Controller flow: `startCommanderSelection` → pending choices; vote →
  finalize; `onWaveComplete` → pending reward choices; `handleRewardVote` →
  reward applied + next wave when all voted.
- `SchematicUnlockPacket` serialization round-trip.
